# 日语学习档案规范

本目录保存持久化的日语学习内容。

## 内容原则

- 每篇稿件使用一个独立文件；
- 保留原说话人的自然、即兴和口语化风格；
- 修正自动转写错误和影响理解的主播口误；
- 不确定内容使用“听写存疑”或“专有名词存疑”标记；
- 翻译必须完整，不得用摘要代替；
- 讲解面向“N4 已通过、正在学习 N3”的用户；
- 重点收录适合当前学习阶段的进阶表达和自然口语表达；
- 词汇和语法数据严禁包含 JLPT 等级字段或等级标签；
- 普通 N5、N4 内容无需讲解，除非在当前语境中存在特殊用法；
- 重点句解析应说明句子结构、口语省略、上下文逻辑和可迁移表达；
- 不得为了让表达更漂亮而改变主播的原意、立场或语气。

## 数据规则

- 数据必须满足项目中的 `StudyArticle` 类型；
- 不生成或保存 `subtitle`；`description` 必须使用日文，简洁说明稿件主题与内容；
- 不生成或保存 `sourceType` 等来源类型信息；本项目稿件均默认为 YouTube 自动转写；
- `url` 保存用户提供的博客原始链接；不得根据文稿猜测或自行生成，用户未提供时必须询问；
- `speakers` 保存已确认的说话人名称；多人稿件由页面自动标注“合作”；无法从稿件中可靠识别说话人时，先询问用户；
- 不生成、不保存也不展示主题标签或 `tags` 字段；
- `slug` 不得与现有文章重复；
- 文件名和 slug 使用 `YYYY-MM-DD-英文简短名称`；
- 同一稿件的后续处理追加到原文件的 `sections`；
- 未处理完时使用 `status: '进行中'`；
- 全部处理完成后改为 `status: '已完成'`；
- 新增文章后登记到 `index.ts`；
- 不因网页格式调整而改写已经确认的日语内容；
- 修改档案数据后运行 `npm run build`，确保数据和页面类型检查通过。
