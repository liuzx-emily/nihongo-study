# STUDY 长稿主代理编排规则

本文件只供用户明确表示文章太长并要求分段处理时的主代理读取。它补充 `instructions/STUDY.md`，不替代其中的学习内容质量规则。文章仅仅看起来很长，不得自动触发本流程。

## 触发与职责

- 主代理负责通读全文、划分部分、串行调度、逐部分验收、最终组装和全局验证。
- 长稿使用三级内容结构：`part` 是供独立子代理处理的批次，`section` 是围绕同一局部主题组织的学习单元，自然段是 `section.japanese` 与 `section.translation` 内通过换行保存的正文段落。三者不得混同；一个 `part` 通常包含多个 `section`，一个 `section` 可包含一个或多个自然段，每个日文自然段原则上不超过 200 字符。
- 主代理第一次通读全文只用于识别文章结构并划分语义完整的部分，不在此阶段生成校对、翻译、语法、重点句或其他学习内容。
- 部分数量按文章结构动态决定，不设固定数量或上下限。语义完整优先于长度均衡。
- 标题、过渡句和跨行残句只能归入一个部分，不得重复、遗漏或截断。

## 部分子代理

- 每个部分必须使用独立子代理，并设置 `fork_turns: "none"`。
- 传给子代理的任务必须包含该部分完整原文、输出文件路径、编号，以及完成任务所需的明确要求；其中必须明确要求区分 `part`、`section` 和自然段、每个日文自然段原则上不超过 200 字符，并保持日中自然段一一对应；不得提供全文路径。
- 子代理只可读取 `instructions/STUDY.md`、`LEARNING_PROFILE.md`、`src/content/AGENTS.md` 和 `src/types.ts`。
- 子代理禁止读取本文件、全文、其他部分原文或其他部分产物。
- 子代理不得把当前部分再次拆成新的 `part`，不得创建子代理、修改内容索引或生成整篇文章元数据。此处“不得再次拆成新的 `part`”不限制其在当前部分内划分多个 `StudySection`，也不限制其按 `STUDY.md` 在每个 `section` 内保留或划分多个自然段。
- 每个子代理只输出对应的 `...-part-N.ts` 文件，并统一导出 `Omit<StudySection, 'id'>[]`。

## 严格串行与验收

- 同一时间只处理一个部分。当前部分尚未完成并通过验收时，禁止启动下一部分子代理。
- 每部分完成后，主代理只复核该部分是否忠实于原文、字段是否齐全、导出类型是否正确、日中自然段是否一一对应，以及 `section` 内是否按语意合理分段、每个日文自然段是否原则上不超过 200 字符，并执行必要的 TypeScript 类型验证。
- 若当前部分包含多个 `section`，却机械地让所有 `section.japanese` 和 `section.translation` 都各自只有一个自然段，主代理必须将其视为异常信号并要求当前子代理逐个复核。只有每个 `section` 都能确认其内容确实只需一个自然段，且该日文自然段不超过 200 字符时，才可通过验收。
- 当前部分验收失败时，只要求当前子代理返工；不得提前启动后续部分，也不得让其他部分代理代为修改。
- 会话中断时保留已经验收的部分产物，记录首个未完成部分；恢复后从该部分继续，不重新生成已验收部分。

## 最终组装

- 所有部分均验收通过后，主代理只按部分编号顺序展开各数组，为所有 section 生成连续且唯一的 ID，添加整篇元数据，并在内容索引中登记文章。
- 最终组装阶段禁止重新通读全文、跨段润色、跨段去重或统一措辞，不得改变已验收的部分学习内容。

## 最终验证

交付前必须完成以下检查：

- 内容索引不存在重复登记。
- 部分展开顺序与 section ID 顺序连续、正确且唯一。
- 所有必填字段存在，公共类型检查通过。
- 所有 `section` 的日中自然段数量与顺序一一对应，每个日文自然段原则上不超过 200 字符，不存在因长稿分批处理而产生的机械单段化。
- 运行 `npm run build` 并确认构建成功。
